# лабораторная работа 1: Классы - Объектная модель данных и Unit-тестов
## Что реализовано
Реализована объектная модель предметной области авиаперевозок с основными сущностями и их связями:
* Семейства самолётов (AircraftFamily): информация о производителях и сериях моделей.
* Модели самолётов (AircraftModel): характеристики, вместимость, дальность полета, связь с семейством.
* Рейсы (Flight): код, маршрут (пункты отправления и приёма), время, назначенная модель.
* Пассажиры (Passenger): идентификаторы, паспортные данные, ФИО и дата рождения.
* Билеты (Ticket): связь пассажиров с рейсами, места, багаж и ручная кладь.

## Данные для тестов
Создан класс TestsDataFixture, содержащий зафиксированные наборы данных:
10 семейств и моделей самолетов;
10 рейсов с детальными маршрутами и временем;
23 пассажира с уникальными данными;
23 билета со связями с рейсами и пассажирами, включая данные по багажу.

### Unit-тесты
Выполнены пять тестов для проверки бизнес-логики и корректности запросов к данным:
* Тест 1 — топ 5 рейсов по количеству пассажиров, проверка упорядочивания и подсчётов;
* Тест 2 — поиск рейсов с минимальной продолжительностью, проверка корректного фильтра;
* Тест 3 — выбор пассажиров определенного рейса без багажа, валидация совпадения ФИО;
* Тест 4 — получение информации по рейсам модели в определённом периоде: подсчёт рейсов, пассажиров и веса багажа;
* Тест 5 — фильтрация рейсов по маршруту (пункт отправления - пункт прибытия) с проверкой ожидаемых кодов рейсов.

## Результат
Создана объектная модель предметной области Airlines с комплексными unit-тестами, покрывающими все требования задания.

# Лабораторная работа 2-3: Авиакомпания — Реализация объектной модели данных и REST API
## Что реализовано:
* Реализованы CRUD-операции для сущностей: рейсы (Flight), пассажиры (Passenger), авиамодели (AircraftModel), семьи моделей (AircraftFamily), билеты (Ticket).
* Реализованы отдельные контроллеры для каждой сущности с использованием репозиторного паттерна.
* Настроены RESTful API-эндпоинты с поддержкой стандартных HTTP-кодов: 200, 201, 204, 400, 404.
* В API реализованы аналитические запросы:
*    Топ-5 рейсов по количеству пассажиров (GetTopFlightsByPassengerCount)
*    Рейсы по модели самолёта за период (GetFlightsByModelAndPeriod)
*    Рейсы с минимальной длительностью (GetFlightsWithMinimalDuration)
*    Пассажиры с нулевым багажом на конкретном рейсе (GetPassengersWithZeroBaggageByFlightCode)
*    Рейсы между двумя точками (GetFlightsFromDepartureToArrival)
* Вся работа с данными — через Entity Framework Core, миграции и реальные таблицы. 

## Что реализовано:
* Используется Entity Framework Core для ORM-модели.
* Добавлены миграции для создания таблиц и связей.
* Реализован DataSeeder для первичного наполнения базы данных тестовыми данными.
* Вся работа с сущностями и аналитикой выполняется через абстракции репозиториев (IRepository).
* AutoMapper настроен для преобразования между сущностями и DTO.
* Модульная архитектура позволяет легко масштабировать и расширять проект.

## Технологический стек
.NET 8 / ASP.NET Core
Entity Framework Core + PostgreSQL
Репозитории и слой инфраструктуры
Swagger/OpenAPI для тестирования API
AutoMapper, миграции, сидирование, unit-тесты
Оркестратор Aspire

## Архитектура решения
Domain — бизнес-модели, сущности и интерфейсы репозиториев
Infrastructure — реализация репозиториев, DbContext, миграции, сидер
Dtos — DTO для сущностей и аналитики, AutoMapper профили
Api — REST-контроллеры, аналитические и CRUD-эндпоинты, Swagger

## Результат
Сервер реализован как модульный REST API, полностью интегрированный с базой данных через EF Core. 
Все бизнес-логика, CRUD-операции и аналитика вынесены в отдельные контроллеры. 
Основной упор сделан на качество API, масштабируемость и удобство для написания unit-тестов.


# Лабораторная работа 4: Реализация сервиса генерации данных и интеграция с сервером через Kafka
## Что реализовано:
* Разработан отдельный сервис-генератор (Airline.Generator), который создает случайные данные билетов с использованием Bogus.
* Реализован Kafka Producer в виде BackgroundService для генерации данных, сериализации в JSON и дальнейшей отправки
* На стороне сервера создан Kafka Consumer (Airline.Api.Kafka.KafkaConsumer), который:
Подписывается на Kafka-топик.
Получает JSON-сообщения.
Выполняет десериализацию в TicketEditDto.
Маппит DTO в доменную сущность Ticket с помощью AutoMapper.
Сохраняет сущность в БД через репозиторий.
Фиксирует offset после успешной обработки.
* Добавлены проверки корректности входящих данных и подробное логирование.
* Интеграция Kafka (Producer + Consumer) добавлена в Aspire — сервисы автоматически поднимаются вместе с брокером сообщений.
* Настроена пакетная отправка и интервальное производство сообщений.
* Сервис-генератор и Api работают независимо друг от друга и связаны только через Kafka-топик.

## Технологический стек
* Kafka (Confluent Kafka Client)
* BackgroundService / Worker Service
* Bogus — генерация тестовых данных
* AutoMapper — преобразование DTO → Entities
* Aspire — оркестрация сервисов

## Архитектура решения
* Airline.Dto — библиотека с DTO-классами, которые выполняют роль контрактов между сервисами.
* Airline.Generator — отдельный Worker-сервис, который объединяет в себе: генератор случайных данных билетов (на основе Bogus) и Kafka Producer
* Airline.Api — основной сервер приложения, содержащий Kafka Consumer, подписанный на Kafka-топик с событиями билетов, десериализацию входящих JSON-сообщений в DTO
* Airline.AppHost — автоматически поднимает Kafka-кластер в контейнерах, конфигурирует переменные окружения и зависимости для Generator и Api

## Результат
Реализована полноценная микросервисная интеграция через брокер сообщений Kafka.
Сервис-генератор автоматически производит реалистичные данные билетов, отправляет их в Kafka пакетами, а сервер асинхронно обрабатывает и сохраняет их в базу данных.
Система устойчива к ошибкам — при недоступности Kafka клиент автоматически повторяет попытки подключения.
Aspire обеспечивает удобный локальный запуск всей экосистемы, включая Kafka, API и генератор данных.
